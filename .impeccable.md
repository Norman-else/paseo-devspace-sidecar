## Design Context

### Users
The project owner is a developer reviewing changes made by a VPS coding agent in a Mac DevSpace worktree. The job is to inspect the current task's actual file changes without identifying infrastructure or choosing from unrelated workspaces.

### Brand Personality
Use Paseo's existing visual language: restrained, precise, and familiar. Let the host theme provide the colors and typography. This is an editor sidebar, not a standalone dashboard.

### Aesthetic Direction
The owner's Claude Code screenshot is the review reference: one continuous document containing every file's diff, with a compact flat file index on its right. Use understated file headers, collapsible code sections, old/new line gutters, syntax highlighting, green/red change backgrounds, and reviewed markers. Paseo supplies the surrounding chrome and theme. Avoid directory trees, workspace cards, implementation identifiers, and navigation to a separate page for each file.

### Design Principles
- Resolve the active task automatically; missing context gets a concise explanation rather than a global picker.
- Keep all file diffs in one continuous review surface; a flat right-hand index scrolls to a file in that same document.
- Only show the composer entry for a session that actually uses DevSpace.
- Show the branch and changes first; paths and infrastructure are secondary.
- Match the host language and theme. Wrap long code automatically at the available width without horizontal scrolling; keep original line numbers on the first visual line.
- Use Paseo's configured code font on desktop and browser, with a readable 14px minimum and matching line height. Keep change backgrounds visibly stronger than the surrounding neutral surface.
- Present PR context as flat editor chrome above the diffs, without card framing, outer margins, or a separate background. Lead with the linked PR number and repository, using consistent 13px text, with branch direction on the right. Remove decorative PR and branch icons; keep only the external-link indicator. Follow with the title and compact icon-and-text statuses. Only the primary PR state uses a filled badge; long check lists stay expandable.
- Use one context header: PR details when a PR exists, otherwise the branch. Put the shared scope tabs, grouped change counts, and actions in a separate thin toolbar immediately above the diff, never inside a PR footer. Avoid duplicate branch titles and refresh buttons. Loading and unavailable PR states must remain distinct from a confirmed missing PR.

- Below 560px panel width, use a deliberate compact layout instead of wrapping desktop rows: left-align branch direction on its own line; keep scope tabs with search/index actions, then counts with collapse/refresh. Preserve all actions and use 44px toolbar touch targets.

- Keep the current file title pinned inside the diff viewport, below the review toolbar. Incoming file titles push the previous title away in both scroll directions. Preserve fold/review actions and keep pinning independent of recycled list rows.
